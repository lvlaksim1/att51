# Att51_export v0.1.18 — согласованный пакет изменений (10.10.2026)

## Единый ввод и два представления

- `desktop/export_batch.py` — единственный сборщик исходных рабочих протоколов. Читает `STRUCT_RM/SOUT_FACTORS` из MDB, связанные **внутренние** `Document` XML (не результат ФГИС) и ресурсную MDB; проверяет факторы, вызывает `prepare_protocol` с одним набором параметров.
- `att51_fsa/export_2025.py` + `att51_fsa/source_snapshot.py` — общий этап формирования одновременно FGIS-представления (`Protocol`) и исходных словесных обозначений (`SourceSnapshot`), до передачи в какой-либо формат. Исключения и порядок показателей одни для обоих выходов.
- `desktop/excel_shared_source.py` — **только** преобразование уже подготовленного `SourceSnapshot` в 26 колонок A–Z. Функций `parse_xml`, `AccessReader`, `read_inventory`, `ResourceCatalog` в Excel-модулях нет.
- `desktop/fgis_export.py` и Excel получают один результат `prepare_batch`. XML выполняет прежнюю проверку по `fileProtocolLoad_v4.xsd`; Excel содержит те же принятые показатели в той же последовательности. Если исходные сведения неполные, файл не создаётся частично.

## Выбор адреса и контактные сведения

- `desktop/organization_sources.py` считывает `STRUCT_ORG.adr`, `STRUCT_ORG.adr2`, `STRUCT_ORG.contact` из выбранной MDB. Ранее эти поля пропускались.
- Окно параметров обоих форматов показывает две радиокнопки **«Вариант 1»** и **«Вариант 2»** с фактическими адресами. Выбор используется при подготовке Excel для столбца G; по умолчанию вариант 1. Если `STRUCT_ORG` не определяет единственную организацию, адрес остаётся `НЕТ ДАННЫХ` (не угадывать).
- Тип адреса пока `НЕТ ДАННЫХ`: в подтверждённой схеме `STRUCT_ORG` соответствующего однозначного текстового атрибута не определено. В итоговый XML адрес не добавлен: оригинальная XSD не подтверждает для него нужный элемент.
- Контакты `STRUCT_ORG.contact` включаются в исходные общие данные и попадают в столбец P; множественные значения с разделителем `; `.

## Прочие исправления Excel

- `.xls` настоящий Excel 97–2003, один лист `TDSheet`.
- Каждое подтверждённое измерение — одна строка, пять столбцов K–O, общие сведения A–J и P–Z только в первой строке.
- Исходные названия оборудования/сотрудников извлекает общий модуль через локальные GUID и оригинальные записи ресурсной MDB — никогда по ID ФГИС. Исходные методики и названия объектов сохраняются до преобразования.
- Единицы измерения: прямые текстовые поля исходного протокола имеют приоритет. Подтверждены два исходных алгоритмических случая — фактор 3 (мг/м³) и фактор 4 (дБА). **Для иных безымянных единиц программы справочник пока не восстановлен**; вымышленное обратное преобразование `MeasurementId` запрещено.
- `TypeObjectId=10` в XML по-прежнему задан исходным VBA-алгоритмом, а не сопоставлением исходного типа. Пока не найден текстовый источник, Excel не заполняет его наугад.
- Даты B, C, D, Q, S, U сохраняются настоящими числами дат Excel с видом `ДД.ММ.ГГГГ`, не строкой ISO. Пустые подтверждённо отсутствующие значения остаются `НЕТ ДАННЫХ`.
- Все A–Z проходят `EntireColumn.AutoFit()` по готовой таблице.

## Обновление одним окном

- `desktop/update_overlay.ps1` — отдельный процесс Windows PowerShell с окном ходa обновления. Главное приложение закрывается только когда окно уже показано. Фактическая загрузка показана в первой части полосы, контроль SHA-256 обязателен.
- Установщик `update.iss` запускается с `/VERYSILENT` без мастера и кнопки «Завершить». Передаёт реальный ход через `CurInstallProgressChanged` в `updates/install.progress`; та же полоса сохраняется до запуска нового GUI и сигнала `updates/newapp.ready`.
- Все файлы остаются в `ProgramData\Att51_export`; сценарий не добавляет внешних пользовательских ресурсов. Обновление не содержит секции `[Icons]` — ярлык рабочего стола не удаляется/не пересоздаётся.
- **Ограничение перехода:** версия v0.1.17 при переходе на v0.1.18 всё ещё использует собственный старый код обновления. Новый механизм действует для перехода **из v0.1.18 в следующие версии**.
- CI: https://github.com/lvlaksim1/att51/actions/runs/38007042272 — Windows сборка, тесты, установка/обновление/удаление с результатом success. Непрерывный GUI-переход через реальную сеть требует пользовательского полевого испытания.

## Открытые задачи

1. Полевой XLS для тех же 11 протоколов: подтвердить число показателей XML=Excel и полноту текста каждой строки.
2. Восстановить из первичных источников текстовые единицы для всех остальных `MeasurementId`, без подстановки неподтверждённых словарей.
3. Определить источник словесного типа объекта (`TypeObjectId`) и типа адреса.
4. Убедиться на клиентском ПК, что после v0.1.18 следующее обновление показывает одно непрерывное окно и ярлык физически остаётся на месте.
