# Восстановление формирования XML ФГИС ФСА из VBA оригинала

Дата исследования: **09.10.2026**. Исходный оригинал: `extracted/app/Attestation51.dot`, схема `extracted/app/fileProtocolLoad_v4.xsd`. Извлечение VBA произведено через `tools/audit_vba_fsa.py` в GitHub Actions **только статическим чтением** (`oletools`), без исполнения чужих макросов или изменения рабочих MDB. Ни одна пользовательская исходная база, сотрудник или номер прибора не опубликованы.

Числовые исходные статусы `DataStatusId = 20` («Черновик») либо `13` («Отправлен») берутся из списка формы, `ProtocolStatusId = 6`.

Новая реализация **явно исправляет конфликт**, формируя только числа. Это отступление от фактического текста VBA при сохранении семантики кодов.

Для фактора 13 «Тяжесть трудового процесса», 14 «Напряженность трудового процесса».
- `v52_exp_fgis_ra2025.get_ResearchObjects2025` (340–347): для 13 переключатель прямые/итоговые; 14 — `read_napr_params`.
- `read_tyag_params_direct` (1253–1362): `Document/count_params2/param`, `bm_1*`/ `bm_2*`/ `bm_4*`, соответствующие единицы и показатели 37 (масса), 42 (расстояние), 39 (время), фильтры.
- `read_tyag_params_itog` (857–1247): `Document/izm_data/zone/param`, 25 основных ветвей `bm`, коды справочника 2025, четыре суммарных показателя только по разрешённому флажку, 12 вариантов `poza_id`, исходное `U095`.
- `read_napr_params` (657–852): 12 ветвей `bm_id`/`bm`, восемь переключателей включения показателей, два специальных показателя с условием наличия МИ НТП.ИНТ-17.01-2018, поддержка `U095`.
- `get_PERS_data` (4637–4709): измеритель из `factor/persons` → роль 1; руководитель из `factor/boss` → роль 2; эксперт из `factor/exp_persons` → роль 3. Для `protocol2019` руководитель из `factor/boss/pers`. ФГИС ID определяется через ресурсную таблицу `FGIS_RA`; должность для XML из исходного поля `pers.fgis_state`. В оригинале при отсутствующих привязках предупреждения/ошибки, не случайные ID.
- Исходный `fileProtocolLoad_v4.xsd`: числовые `EquipmentId` (`xs:unsignedLong`), `ApprovedUserDetails/idFullName` (`xs:int`), `DataStatusId`/`ProtocolStatusId` (`xs:int`); `ResearchObjectInfo` требует согласованную методику. Прохождение XSD само по себе не означает приёма порталом.

При недостающих обязательных реквизитах выходные `fsa_prot*.xml` **не создаются**, ошибки записываются локально в `%ProgramData%/Att51_export/reports/Проверка_и_формирование_XML_ФГИС.txt`. Пользователь может явно предоставить необходимые реквизиты заказчика и дату заявки в локальной форме; они не загружаются в публичный репозиторий. Исходные MDB/XML открываются только на чтение, сохраняются только собственные отчёты и итоговые файлы в папке приложения.

## Границы готовности

- Установочная база `res_orgs.mdb` ранее имела нулевые карточки приборов/сотрудников и не содержала FGIS_RA. Настоящий XML по этим данным невозможен без проверенных ФГИС ID. Сырые GUID сохраняются в локальной диагностике, но не вставляются в числовую схему.
- Путь получения `v5_org_options.query_date` автоматически из реальной `struct_org` и связанных данных требует дальнейшего разбора; пока исходная дата заявки вводится владельцем как явное значение.
- Номера/имена рабочих мест не получаются диагностическим подбором полей. Для объекта `FullNameObject` используется **именно подтверждённое название фактора**, а не произвольное имя рабочего места. Схема рабочих мест подлежит отдельной проработке.
- Не все варианты исходной формы экспорта и сводных XML перенесены. Переключатели, которые не указаны явно, остаются предметом сверки и не служат доказательством эквивалентности.
- Не выполнено эталонное сравнение полного XML с выгрузкой оригинальной программы на одной заполненной MDB и проверка приёма ФГИС. Этот выпуск является проверяемым независимым генератором **с обязательной блокировкой неготовых данных**, а не гарантированно принятым XML.

Исходные публичные проверки исходного VBA: [№37938029784](https://github.com/lvlaksim1/att51/actions/runs/37938029784), [№37938943365](https://github.com/lvlaksim1/att51/actions/runs/37938943365), [№37939657134](https://github.com/lvlaksim1/att51/actions/runs/37939657134), [№37940231243](https://github.com/lvlaksim1/att51/actions/runs/37940231243). ## Дополнительный анализ по диагностике v0.1.9, 09.10.2026

Владелец передал локальный отчёт после запуска третьей команды: пять внутренних протоколов найдены, завершённых для XML — 0. Причины группируются по общему полю даты заявки, числовым FGIS ID оборудования/персонала, сопоставлению НД/методик, зависимым результатам измерений. Показатели физически присутствуют в исходных XML, их неподготовленность не означает отсутствие измерений. Конфиденциальные значения из отчёта **не публикуются**.

Установленные дополнительные положения из оригинального `Attestation51.dot`:
- `v5_org_options.fill_org_info`, строки 2004–2021: организация читается как `select * from struct_org where id = org_id`; GUID из `struct_org.mguid`, ИНН из `struct_org.inn`, ОГРН из `struct_org.short_caption`, название из `struct_org.org`, ФИО руководителя из `struct_org.fio`.
- `v5_org_options.fill_org_info_XML`, строки 2024–2063: файл дополнительных сведений расположен по `main_fs_path/000_org_data/<org_guid>/adv_data.xml`; дата подачи задания из `Document/dop_info/@query_date`.
- `v52_exp_fgis_ra.read_pers_info`, строки 599–616: исходная **должность ФГИС** читается из `ATT_PERSON.no_dop_fld2`; поле `ATT_PERSON.dolg` — отдельное и не может её заменять. Это восстановлено в `ResourceCatalog.from_rows`.
- Оригинальная `fileProtocolLoad_v4.xsd`: `Equipment/EquipmentDetails/EquipmentId` и `ApprovedUserDetails/idFullName` требуют числа; текстовые исходные GUID и номер прибора не подходят. В то же время `ResearchObjectInfo/UniqueMethod` и `UniqueMethodik` — предусмотренные схемой альтернативы для нормативных документов вне справочника, но их применение допустимо только после воспроизведения соответствующих условий VBA; код не подставляет выдуманные методики.

В следующем выпуске добавлено:
- Автоматическое чтение доступных `STRUCT_ORG` и `adv_data.xml` **только при ровно одной организации**; при нескольких организациях выбор автоматически не делается, сохранён ручной ввод.
- Проверка даты **в диалоговом окне**, а не пять раз в отчёте.
- Подробное сообщение о выбранной ресурсной базе с количеством приборов, сотрудников, НД, связей FGIS ID и отсутствующих таблиц. Это позволяет отличить подозрительную базу от реально отсутствующих карточек, но не доказывает самостоятельно, какая база является боевой.
- При несопоставлении исходные GUID приборов/сотрудников и исходное название НД указываются в **локальном** отчёте, а повторяющиеся следствия ошибок методик свёрнуты до числа неподготовленных показателей и исходных позиций.
- Положительное сквозное синтетическое испытание: исходный XML + `ResourceCatalog` + методики + роли → `Protocol` → итоговый XML и XSD. Реальное принятие порталом не проверялось.

Открытая задача: сверить `[DB_res]` в `options.ini` оригинала с выбранной ресурсной MDB, получить отчет с дополнительными счётчиками, проверить дальнейшие способы представления методик и отдельные режимы оригинального экспорта. Никогда не заменять действительное использование прибора утверждением `NoEquipmentInfo=true` только из-за отсутствия ID.

### Реализация и ограничения

- Новые `fsa_xml_module/att51_fsa/aerosol_2025.py`, тесты `test_aerosol_2025.py`: концентрации с сохранением оригинального текста, источников, кодов и порядка; переключатели режимов в окне GUI `Att51_export`.
- `methods.py` разрешает исходное текстовое `UniqueMethod` **лишь если ресурсный НД найден однозначно по точному источнику и соответствует этому фактору**. При дубликатах, совпадении только по иному фактору, отсутствии названия или невозможности сопоставления сохраняется блокировка. `resources.py` считает дубликаты даже при неполных/безчисловых названиях.
- Для фактора 3 перенос ограничен приведёнными проверенными режимами. Произвольные настройки справочника химических веществ, `oa_matters` и отличные варианты формы оригинала не считаются доказанно эквивалентными. Программа по-прежнему не подставляет вымышленные ID приборов, сотрудников и методик.
- **Важно:** все пять ранее подготовленных протоколов не должны исчезать из расчёта; запись итогового XML допускается только при готовности **всех 11** и успешной XSD. Прохождение автоматических проверок Windows не подтверждает приём конкретного XML порталом ФГИС.
- Выпуск [v0.1.13](https://github.com/lvlaksim1/att51/releases/tag/v0.1.13) в составе **полного установщика и файла обновления**; [Windows испытания #37962384408](https://github.com/lvlaksim1/att51/actions/runs/37962384408): успешно. Никакие частные MDB, связанные XML и имя/содержимое пользователей в репозиторий не загружены.

**Полевое следующее действие:** пользователь устанавливает `v0.1.13`, выбирает прежнюю рабочую MDB, связанный каталог внутренних XML, `res_orgs.mdb`, исходный `fgis_ra.ini` (если использовался), указывает реально применявшиеся флажки АПФД и создаёт новый `Проверка_и_формирование_XML_ФГИС.txt`. Если конкретные факторы остаются заблокированными, сравнить их по соответствующим внутренним XML/справочнику, а не по внешнему MDB в отрыве от папки `_files`.
