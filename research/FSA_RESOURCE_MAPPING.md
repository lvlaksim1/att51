# Сопоставление ресурсов при формировании XML ФГИС ФСА

**Дата:** 09.10.2026. **Основа:** подлинные VBA из `extracted/app/Attestation51.dot`, подлинная `extracted/app/res_orgs.mdb`; без запуска Word или исходной программы.

## Подтверждённые исходные таблицы и поля

Проверка колонок с помощью ADO/Jet в Windows: [GitHub Actions #37870387468](https://github.com/lvlaksim1/att51/actions/runs/37870387468).

| Таблица | В установочном образце | Исходное назначение |
|---|---|---|
| `ATT_DEVICE` | Есть, поля `id, mguid, factory_num, name, ...` | Средства измерений |
| `ATT_PERSON` | Есть, поля `id, mguid, fio, snils, dolg, ...` | Сотрудники |
| `DIC_ND` | Есть, поля `id, mguid, name, factor_id, typ, ...` | Нормативные документы |
| `ATT_DOP_INFO` | Есть | Дополнительные сведения по приборам |
| `FGIS_RA` | **Отсутствует в исходном образце** | Привязки `rec_type/rec_guid → IntValue` |
| `DIC_ND_INFO` | **Отсутствует в исходном образце** | `nd_id, key_ctxt, dop2, dop4, dop5` |
| `DIC_ND_SYN` | **Отсутствует в исходном образце** | Синонимы НД |
| `DIC_ND_OA_METHODS` | **Отсутствует в исходном образце** | Дополнительные методики области аккредитации |

Исходная программа создаёт или дополняет часть отсутствующих таблиц во время открытия ресурсной базы: `v5_res_main.chk_fgis_ra`, `v5_options_dic.CreateTable_DIC_ND_INFO`. **Независимый модуль не должен делать этого в рабочих данных**: он открывает MDB только на чтение и сообщает об отсутствующей схеме/привязках.

В шаблоне `ATT_PERSON` ещё отсутствуют некоторые новые колонки ФИО по частям; они могут появиться при миграции основной программой. Модуль обрабатывает их отсутствие, не пытаясь выполнять `ALTER TABLE`.

## Фактическое происхождение алгоритмов

**Приборы:** `v5_res_main.fill_si_errs` читает `ATT_DEVICE LEFT JOIN ATT_DOP_INFO`; `v5_res_main.get_si_by_num` ищет по `mguid`, после этого по точному заводскому номеру `factory_num`, если номер содержит цифры. `v52_exp_fgis_ra.get_fgis_dev_id` ищет соответствие по внутреннему `mguid` в данных `FGIS_RA` (`rec_type=0`).

**Сотрудники:** `v5_res_main.fil_pers_data` читает `ATT_PERSON`; `v52_exp_fgis_ra.get_pers_info` ищет сначала по `mguid`, затем по СНИЛС с цифрами; `get_fgis_pers_id` сопоставляет `mguid` с `FGIS_RA` (`rec_type=1`). Рабочая запись выбирается из `Document/factor/persons|exp_persons|boss`, либо из `Document/info/` для сводных протоколов.

**Нормативные документы:** `v5_options_dic.fill_dic` читает `DIC_ND` с добавочными полями `DIC_ND_INFO`. Процедура `prot_api.get_nd_hash` сохраняет из строки только цифры и русские буквы `а, о, и, я, е`. `v5_options_dic.get_nd_by_name` выполняет:

1. По хешу (в том числе синонимов) **и конкретному фактору**, когда он задан.
2. По хешу/синонимам без проверки фактора; при нескольких совпадениях предупреждает пользователя.
3. По сокращённому названию `key_ctxt`, если оно достаточно длинное.
4. По точному полному имени, когда хеш исходной строки пуст.

`v52_exp_fgis_ra.get_ND_data` выбирает нормативные документы оценки из `Document/nd_data/nd` для обычного протокола и `Document/info/nd_data/nd` для сводного. Перед поиском выполняется `del_bad_chars` — отбрасывание начальных дефисов с последующей обрезкой пробелов. Если документ не найден, оригинал **блокирует выгрузку**. Если он найден без идентификатора ФГИС, возможны особые разделы «Иной НД»/«Уникальная методика» с отдельными условиями.

**Назначение метода измерения:** `v52_exp_fgis_ra2025.get_DocNameId` применяет три прохода: явная ссылка на НД, назначенный `DIC_ND_INFO.dop4` приоритет, запасной выбор. До этого номер `dop2`, `dop4`, `dop5` и GUID документа связываются с методом из внутреннего протокола.

## Выполненный перенос

| Компонент | Реализация | Проверка |
|---|---|---|
| Открытие исходной MDB и просмотр таблиц | `sources.py:AccessReader` | Windows Jet/ADO, только чтение |
| Выбор местного или внешнего `res_orgs.mdb` по `[DB_res]` | `resources.py:resource_mdb_path` | Испытания путей |
| Приборы по GUID/номеру и `FGIS_RA` | `resources.py:ResourceCatalog.device` | Испытания порядка поиска |
| Сотрудники по GUID/СНИЛС и `FGIS_RA` | `resources.py:ResourceCatalog.person` | Испытания порядка поиска |
| НД по фактору, хешу, синонимам, краткому/полному названию | `resources.py:ResourceCatalog.nd` | Испытания 4 способов |
| Чтение привязок приборов, сотрудников и НД из XML обычного/сводного протокола | `resource_xml.py:inspect_protocol_resources` | Испытания ролей, флагов, пропусков |
| Связь НД из `res_orgs.mdb` с трёхпроходным подбором методики | `methods.py:bind_methods_from_catalog` | Испытания идентификаторов и приоритетов |
| Диагностическая команда | `python -m att51_fsa inspect-resources` | Отдельная команда без создания итогового файла |

Применяется строгая политика отсутствующих данных: **не выдумывать** ID ФГИС; отсутствие соответствия отмечать; рабочая запись `fsa_prot.xml` остаётся отключённой.

## Неустановленная полная эквивалентность

- Случаи подбора кратких названий через VBA `Like` содержат дополнительные особенности специальных символов; соответствие пока оценивается консервативно, такие результаты помечаются для проверки.
- Работа с личными данными и справочниками в **заполненных базах пользователя** пока не испытана. Исходный установочный образец почти пуст и не содержит таблиц привязок.
- Не закончена сборка всех обязательных разделов `ResearchObjectInfo` и обработка всех факторов. Реальный выходной XML не сравнивался с экспортом оригинала на идентичных данных.

**Не загружать заполненные рабочие базы, отчёты диагностики или XML с персональными сведениями в публичный GitHub.**
