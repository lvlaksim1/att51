# Единая подготовка данных для XML и Excel — v0.1.16 (10.10.2026)

## Причина переделки
Полевое сравнение владельца показало **11 протоколов, 58 показателей в XML, 172 строки показателей в Excel**. Ранее Excel использовал самостоятельный обход всех исходных XML-параметров, а XML — проверенный набор алгоритмов факторов. Общая база файлов не гарантировала одинаковый состав показателей.

## Исправленная архитектура
Оба формата читают исходные внутренние `Document` и одну ресурсную MDB, затем вызывают **одну и ту же** функцию `att51_fsa.export_2025.prepare_protocol`, с одинаковыми параметрами `Original2025Options` (включая тяжесть и АПФД).

В `att51_fsa.pipeline_2025.FieldTrace` исходные сведения `source_draft`, `original_method_name` и `original_oa_method` сохраняются **до подстановки FGIS ID**. `PreparedProtocol.source_traces` содержит **ровно принятые XML-показатели**, в том же порядке. `desktop/excel_shared_source.py` переводит их в исходные текстовые записи Excel; отдельного поиска или добавления показателей нет. При рассогласовании числа подготовленных показателей операция завершается ошибкой, не создавая частичный файл.

Для Excel исходные наименования приборов и сотрудников берутся из записей `ATT_DEVICE` и `ATT_PERSON` ресурсной MDB по оригинальным ссылкам; ФГИС-ID не подставляются. Методика берётся из выбранного исходного `nd_data/nd`; метод — текстовое исходное описание ОА без заключённого в фигурные скобки числового кода. Исходный заказчик, его ИНН и дата заявки сохраняются из тех же входных значений, что используют XML. Если текст в доступных оригинальных источниках не найден, применяется `НЕТ ДАННЫХ`. Цифровые коды не декодируются догадками.

Формат XLS: 26 колонок A–Z, ровно один лист `TDSheet`, значения показателя K–O; общие сведения в первой строке каждого протокола, последующие строки заполняются исключительно K–O. Несколько значений одного поля объединяются через `; `.

Оба пункта главного интерфейса `Выгрузить XML` и `Выгрузить Excel` используют **одну форму** ввода заказчика и параметров факторов. Не подготовленные общим механизмом XML данные не заменяются для Excel произвольными или непроверенными строками.

## Обновление
Одно нажатие `Обновить` закрывает основную программу без подтверждения. Отдельный процесс показывает индикатор загрузки с фактическим процентом скачивания и проверяет SHA-256, затем освобождает `Att51_export.exe`. Встроенный в Windows PowerShell помощник ждёт завершения обоих процессов и запускает Inno Setup с `/SILENT /SUPPRESSMSGBOXES /NORESTART /RUNAFTERUPDATE=1`. Во время установки показывается ход установки без страниц мастера, после успеха автоматически открывается новая версия. При ошибке допускается отдельное сообщение.

Установщик обновления намеренно не имеет `[Icons]`: он не создаёт и не переписывает ярлык на рабочем столе или его координаты. Для нового полного установщика возможность создания ярлыка остаётся.

## Проверки и ограничения
Тесты `desktop/tests/test_excel_export.py` подтверждают привязку количества строк Excel к `protocol.research_objects`, сохранение исходного текста до преобразования, отсутствие кодов ФГИС, общие сведения только в первой строке, прекращение выгрузки при ошибках, совпадение фактических значений. Проверки `desktop/tests/test_updater.py` и Windows-инсталлятора подтверждают управление обновлением и неизменность файла ярлыка (содержимого и времени изменения).

**Ограничения:** реальная численность показателей на частной базе пользователя после переделки, полнота названий при отсутствии текстовых полей, отображение окна обновления и автозапуск в его конкретной оболочке Windows, позиция ярлыка при внешних изменениях параметров рабочего стола и приём порталом ФГИС требуют полевых испытаний. Ни частные исходные MDB, ни реальные персональные данные в публичный GitHub не загружаются.
