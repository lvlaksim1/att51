# Рабочий цикл «Аттестация-5.1 (СОУТ)»

**Источник:** только оригинальные установочные файлы версии, исследуемой в `att51`. Сторонние проекты и их переработки не использовались. Дата исследования: 09.10.2026.

**Метод:** статический анализ `attstart51.exe`, извлечение и чтение всех 569 модулей VBA из `extracted/app/Attestation51.dot`, анализ отдельных VBA-модулей `start51.dot`, `shum_prg_sout.dot`, `shum_prg2019_sout.dot`, `him_prg_sout.dot`, `micro_prg2019_sout.dot`, `karta_prg_sout.dot`, `apfd_prg2019_sout.dot`, изучение `options.ini` и `xsl/`. Код не исполнялся.

## Ключевая архитектурная особенность

**Приложение представляет собой систему, работающую внутри Microsoft Word**, а не самостоятельную Windows-программу с полностью независимым интерфейсом.

- `attstart51.exe` — 32-битный загрузчик Visual Basic 6. В строках его кода присутствуют `word.application`, `Documents`, `start51.dot`.
- `start51.dot` — запускающий шаблон Word. Его обработчик `ThisDocument.Document_New` проверяет состояние регистрации/совместимость и подключает `Attestation51.dot` посредством `AddIns.Add(..., Install:=True)`.
- `Attestation51.dot` — главная надстройка Word: **569 успешно прочитанных VBA-модулей**; меню, формы, работа с рабочими местами, Access, протоколами, отчётами и обменом данными.
- Шаблоны документов по каждому фактору тоже содержат собственные VBA-модули с обработчиками команд «Заполнить таблицу», «Оценка условий труда», «Отправить в базу РМ». **Расчёты распределены по шаблонам**, не находятся исключительно в главной надстройке.

## Цикл оператора и вызовы программы

| Этап | Действие оператора | Подтверждённая реализация |
|---|---|---|
| 1. Запуск | Открытие «Аттестации» | `attstart51.exe` → Microsoft Word / `start51.dot` → `Attestation51.dot`; `ThisDocument.Document_New` |
| 2. Выбор базы | Выбрать имеющуюся базу рабочих мест или создать новую | `menu_sout.base_RM` → `v51_org_tree` → `v5_attest_DB.init_db`. Путь считывается из `options.ini`, секция `[DB]`, ключ `sout_path`. Новая база создаётся `v5_attest_DB.create_DB` копированием `model/ARMv51.MDB` |
| 3. Объект и рабочие места | Организация → подразделения → рабочие места (РМ), аналогичные РМ | `v51_org_tree`; таблицы `struct_org`, `struct_ceh`, `struct_uch`, `struct_rm`, `anal_group` |
| 4. Подготовка измерений | Выбрать РМ, указать факторы, рабочие зоны, параметры, дополнительные сведения | `v51_org_tree.tree_NodeClick`, `v5_factors_frm`, `v51_dop_info_rm`; таблицы `per_rzona`, `per_genfactors`, `sout_ident` и др. |
| 5. Создание протокола | Выбрать вид измерения и создать Word-документ | `v51_org_tree.new_protocol_btn_Click` → `need_factors_mod.new_protocol` → соответствующая функция `menu_sout` → `v51_Attest.create_protocol`; выбор шаблона из `options.ini`, `[templates]` |
| 6. Привязка | Указать РМ для протокола | `v51_org_tree.sel_RM`: запись `rm_id`, `rm_guid`, `org_id`, номера РМ, характеристик, связанных данных в `ActiveDocument.Variables`; обновление полей/таблиц Word |
| 7. Ввод и оценка | Заполнить таблицу измерений, выполнить расчёты, получить класс условий труда | Макросы `toolbar_mod.Заполнить_таблицу` / `toolbar_mod.Оценка_условий_труда` **конкретного шаблона** вызывают его `main_mod`, `main_frm` и другие специализированные процедуры |
| 8. Сохранение результата | Выполнить «Отправить в базу РМ» | Макрос `toolbar_mod.Отправить_в_базу_РМ` → `v51_savedoc.send_to_base_rm`: проверка РМ, сохранение DOC/DOCX, изменение строк MDB, формирование XML и регистрация действий |
| 9. Сводные документы | Карта СОУТ, сводные протоколы, ведомости, заключения, отчёты | `v51_org_tree` → `v5_otchet`, `v51_otchet`, `xslt_reports_mod`, специализированные `.dot`, `.xsl` и `.xlt/.xltx` |
| 10. Обмен | Экспорт организации/результатов в XML, специальные выгрузки | `v51_org_tree.XML_btn_Click` → `v5_xml_export.export`; отдельно `v52_exp_fgis_ra` для ФГИС РА, `v52_exp_xml` для иных вариантов экспорта |

### Сохранение — важнейший участок цикла

Для базы РМ вида `ARMv51.MDB` создаётся параллельный каталог `ARMv51_files/`.

При сохранении протокола `v51_savedoc.send_to_base_rm`:

1. Проверяет версию документа, `rm_id` и `rm_guid`, существование этого РМ в активной базе, доступ к каталогу.
2. Сохраняет файл Word по схеме `<имя БД>_files/<GUID рабочего места>/<название протокола>.doc[х]`.
3. Добавляет либо обновляет строку `sout_factors`: код фактора, название, КУТ (`kut`), дата измерения, **относительный путь к документу**, GUID фактора, дата сохранения.
4. Обновляет `sout_factor_info` с мерами и назначением; сохраняет `factors.dat` в каталоге РМ.
5. Создаёт `<имя протокола>.xml` в подкаталоге `<GUID РМ>/xml/`. XML включает информацию о документе, факторе, классе, измерениях и дополнительных параметрах; структура зависит от типа шаблона.
6. Для карты РМ использует другой путь: запись в `struct_rm` (`file_sout`, `kut1`, `kut2`), `rm.dat`, `Save_XML_karta`.
7. Добавляет запись в журнал действий, сохраняет сведения о последнем РМ/документе в `options.ini`.

Это доказывает, что данные исследования **не находятся в одном MDB-файле**. Они распределены по `MDB + DOC/DOCX + XML` и должны переноситься/резервироваться согласованно.

**Важно:** обычное сохранение Word и специализированная команда **«Отправить в базу РМ»** не эквивалентны: последняя выполняет отдельные операции с MDB и XML.

### Как выполняется расчёт

Расчёт не является единым «универсальным вычислителем». У конкретных шаблонов имеется собственная цепочка вызовов:

- `shum_prg2019_sout.dot`: `toolbar_mod.Оценка_условий_труда` → `main_mod.Оценка_условий_труда` → `att_zakl`.
- `him_prg_sout.dot`: аналогичный вызов `main_mod` плюс дополнительные проверки суммирования веществ и неопределённости U095.
- `micro_prg2019_sout.dot`: отдельные `main_frm` и `main_mod` для ввода и расчётов.
- `karta_prg_sout.dot`: `toolbar_mod.Оценка_условий_труда` → `v51_Attest.fill_s030` для заполнения соответствующего раздела карты.

Наличие вычислительных макросов установлено. **Полная правильность каждого расчёта по методике СОУТ пока не проверялась.**

### Выгрузка и отчёты

`xslt_reports_mod` собирает данные из выбранных рабочих мест и сформированных документов, строит промежуточные XML и использует шаблоны `xsl/` для сводных форм Word/Excel. Отдельные процедуры формируют экспортные XML: `v5_xml_export.export`, `v52_exp_xml`, `v52_exp_fgis_ra`. **Прямая передача данных по сети в ФГИС в рамках этого исследования не доказана** — следует различать *создание файла экспорта* и *непосредственную отправку в государственную систему*.

### Контроль при запуске и технические особенности

- `start51.dot` проверяет регистрацию, совместимость компонентов Word/Office, добавляет основную надстройку. Для серверных сценариев есть отдельные условия лицензирования.
- `v5_attest_DB.init_db` после подключения к Access проверяет таблицы/представления и может выполнять их обновление (`ALTER TABLE`, создание недостающих структур). Это означает: **открытие старой базы потенциально модифицирует её**, поэтому исследовать следует копии.
- `v5_attest_DB.init_user_db` отдельно использует `user_data.mdb`.
- Для части лицензионных проверок предусмотрено сетевое обращение к сервису разработчика; это не следует смешивать с обменом данными ФГИС.
- В `options.ini` пакета указан внутренний параметр версии `5.1.1624`; он отличается от версии исследуемого установщика `5.1.1739`. Причину расхождения необходимо проверить отдельно, не трактовать его как доказательство двух разных установленных версий.

## Что ещё не подтверждено

1. Фактическое поведение запуска и окна Word в Windows — выполнялось **только статическое исследование**.
2. Точные результаты математических вычислений для всех факторов и всех разновидностей протоколов.
3. В какой последовательности оператор конкретной организации использует все дополнительные формы; доступно много необязательных ветвей.
4. Корректность работы экспорта с текущими государственными информационными системами и необходимость действий пользователя вне программы.
5. Взаимозависимости всех справочников MDB и полное описание связей таблиц.
