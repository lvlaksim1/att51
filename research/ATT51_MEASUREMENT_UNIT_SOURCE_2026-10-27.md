# Где оригинальная «Аттестация-5.1» получает единицы измерения для XML ФГИС
Дата: 27.10.2026. Анализ только исходников, без изменения продуктовой реализации.

## Проверенное происхождение

Исследован ORIGINAL `extracted/app/Attestation51.dot`, модули `v52_exp_fgis_ra2025`, `v52_exp_fgis_ra`, `v52_exp_fgis_ra_syn3` (извлечение VBA без исполнения). Журнал проверки:
- https://github.com/lvlaksim1/att51/actions/runs/40426529291
- https://github.com/lvlaksim1/att51/actions/runs/40427048383
- https://github.com/lvlaksim1/att51/actions/runs/40427649674

Механизм:
1. `v52_exp_fgis_ra2025.get_ResearchObjects2025`, строки 304–349: по `facid` вызывает отдельные `read_...` (в том числе 1/3 химический, 4 шум, 7/8 вибрация, 11 микроклимат, 12 освещение, 13/14 трудовой процесс, 26 УФ).
2. Каждая `read_...` берёт значение из исходного `Document/izm_data` (и специализированных разделов) и назначает **код единицы ФГИС** в поле `fgis_ra_res_obj_cls.MeasurementId`, как правило **жёстко заданной константой в VBA**. Для вибрации вспомогательная `AddParam` (строка 2561) устанавливает `MeasurementId="429"` (дБ).
3. `v52_exp_fgis_ra.save_XML`, строки 1863–1875: если не установлен режим уникального показателя, формируется `fgis_id_dop = "id" + res_obj.Directory + "_" + res_obj.IndicatorId`. Чтение `System.PrivateProfileString(path_attest_folder + "\\fgis_ra.ini", "Measurements", fgis_id_dop)` при непустом значении **заменяет** `res_obj.MeasurementId`. Следовательно, итоговый код может отличаться от зашитого в VBA.
4. Строки 1961–1969: в XML записывается `MeasurementId`, а необязательный `UniqueMeasurement` получается через `v52_exp_fgis_ra_syn3.get_measurement(res_obj)`.
5. `v52_exp_fgis_ra_syn3.get_measurement`, строки 384–402: выбирает `IndicatorId2`, когда он задан, иначе `IndicatorId`; ищет в `oa_params` по `param.id`, возвращает `param.norm`. При пустом результате берёт `IndicatorId3` (специальный случай ЭМП). `init_coll`, строки 414+, формирует `oa_params`; `param.norm` берётся из `fgis_ra.ini/[UniqueMeasurement]`, ключ = **идентификатор показателя**, а не код единицы. Это пользовательский комментарий к единице, не расшифровка всех `MeasurementId`.
6. Исходная XSD `extracted/app/fileProtocolLoad_v4.xsd`, строки 327–335, описывает `MeasurementId` как идентификатор единицы и `UniqueMeasurement` как комментарий. Программа считает `MeasurementId` обязательным в текущем алгоритме несмотря на `minOccurs=0` в XSD.

Некоторые единицы назначаются строго по `bm`/`bm_id`, а не одному `facid`. Коды `985` и `987` в блоке тяжести ссылаются в комментарии на внешний документ, точной текстовой расшифровки исходник не даёт. Также есть противоречивый комментарий возле кода `559` (на одной строке указан Дж/м², на другой Дж/см²); автоматически считать такие комментарии проверенным справочником запрещено.

## Проверка частного источника

В `ARMv51_files.zip` из диалога проверено 73 индивидуальных `Document/factor`: отдельные текстовые атрибуты `unit/ed_izm/edizm/measurement_unit` у измерений не обнаружены; названия единиц присутствуют в части `param/@name` (например, лк, мг/м³, Вт/м², дБА) и в связанных Word-документах. Сама кодовая единица ФГИС обычно определяется VBA.

## Вывод для следующего улучшения Excel

Фактически текущий `desktop/excel_source_batch.py` читает единицу из явных текстовых атрибутов, подписи показателя и Word при вибрации. Он **не использует** проверенную оригинальную связь `facid + bm/bm_id → MeasurementId`, и поэтому теряет данные о единицах. Нужен отдельный доказательный слой отображения единиц с приоритетом: исходный текст конкретного результата → утверждённое соответствие *именно ветви VBA* и кода → при отсутствии доказательств пустая ячейка/предупреждение. Варианты через рабочий `fgis_ra.ini/[Measurements]` учитывать перед расшифровкой кода; комментарий `[UniqueMeasurement]` не путать с наименованием единицы. Отдельные единицы 985/987 и 559 до подтверждения не присваивать по догадке.

Это исследование, не выпуск приложения и не полевой тест новой выгрузки.
