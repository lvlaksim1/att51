# Ход переноса независимого модуля XML ФГИС ФСА

**Дата:** 09.10.2026. **Исходное приложение:** «Аттестация-5.1 (СОУТ)», версия 5.1.1739. **Главный оригинальный источник кода:** `extracted/app/Attestation51.dot` (восстановленные исходные макросы; исполняемый оригинал не запускался).

## Принцип реализации

По прямому указанию владельца `fsa_xml_module/` должен считывать **оригинальные рабочие MDB, XML, настройки и справочники** и применять механизмы оригинального экспортёра. Не допускается необходимость запускать Word, основную программу или импортировать стороннюю переработку `sout-app`.

Реализация строится по частям. Уже перенесённые процедуры сначала возвращают проверяемые промежуточные результаты, затем они будут включены в полную цепочку формирования. Формирование **рабочего** итогового XML пока намеренно заблокировано: нельзя выдавать частичный экспорт за полный.

## Проверка и ограничения достоверности

- Исходные MDB из установщика (`model/ARMv51.MDB` и `res_orgs.mdb`) открываются через 32-разрядный Jet OLE DB 4.0 на Windows **в режиме чтения**. Факт открытия подтверждён GitHub Actions; образцовые таблицы пусты, поэтому работа с заполненной базой **ещё не проверена**.
- По исходной XSD и MSXML 6.0 проверены структура синтетического XML и отклонение нечисловых статусов.
- Тесты охватывают маршруты файлов, категории факторов, обрезание путей, чтение XML, синтетический выходной XML, обе группы протоколов, выбор методики и ветви шума/инфразвука/света.
- Отсутствие ошибок во время синтетических проверок **не означает**, что конечный результат эквивалентен реальному экспортёру. Рабочей команды генерации `fsa_prot.xml` из MDB пока нет.

## Известные границы текущей реализации

1. Не перенесено большинство факторов: химия, вибрация, микроклимат, биология, тяжесть и напряжённость, ЭМП, ультразвук и др.
2. Нет полного независимого справочного разрешения `ATT_DEVICE`, `ATT_PERSON`, `DIC_ND`, `DIC_ND_OA_METHODS`, внешних идентификаторов `FGIS_RA` и подтверждения всех рабочих настроек.
3. Уникальные и запасные методики требуют отдельной проверки; в `resolve_method` возвращается признак `requires_review` при неполной связи, а не придуманное подтверждение.
4. Пользовательская иерархия РМ и видимость подразделений доступны только в работающем интерфейсе оригинала. Сейчас они **передаются вызывающим кодом явно**, иначе точность отбора нельзя гарантировать.
5. Для доказательства совместимости нужна одна согласованная и **обезличенная** выборка: рабочая MDB, `*_files`, текущая ресурсная MDB, настройки и готовый `fsa_prot.xml` оригинала. Нельзя использовать действующие секретные/персональные данные в открытом репозитории.
6. При разных режимах отличаются правила заполнения `ResearchObjectInfo` и персонала; перенос проверять отдельно, а не распространять без доказательств на все факторы.

## Следующая последовательность работ

1. Проверить строение заполненных MDB и ресурсных таблиц, написать независимый точный справочный сопоставитель.
2. Связать выбранные протоколы с измеренными показателями, методиками, приборами и сотрудниками, снабдив каждый результат происхождением.
3. Расширить вычислительные ветви; добавлять отдельные тесты для каждого сочетания параметров исходной формы.
4. Перенести все обязательные блоки выходного XML и только после эталонного сравнения открыть рабочую генерацию.
5. Подготовить вызываемый из Excel/VBA интерфейс, не требующий Word и установленной «Аттестации-5.1».

Текущий приёмочный перечень: [задача № 2](https://github.com/lvlaksim1/att51/issues/2); исходный код и команды: [fsa_xml_module](../fsa_xml_module/README.md).

## Дополнение: связи с оригинальной ресурсной базой (09.10.2026)

- Реализован `ResourceCatalog` (`resources.py`) для считывания **рабочей** ресурсной MDB через Windows ADO без изменения схемы.
- Проверено, что установочный образец `res_orgs.mdb` не содержит `FGIS_RA`, `DIC_ND_INFO`, `DIC_ND_SYN` и `DIC_ND_OA_METHODS`; в оригинале они могут создаваться при открытии базы. Это подтверждено просмотром реальной схемы MDB на Windows: [Actions #37870387468](https://github.com/lvlaksim1/att51/actions/runs/37870387468).
- Восстановлены из исходного VBA правила поиска оборудования (`mguid → factory_num`), сотрудников (`mguid → snils`), ID ФГИС (`FGIS_RA.rec_type + rec_guid → IntValue`), документов (`DIC_ND`/INFO/SYN; по фактору/хешу/синонимам/сокращению/имени) и выбор местной либо общей ресурсной базы через `[DB_res]`.
- Реализована диагностика связей конкретного исходного XML: `resource_xml.py:inspect_protocol_resources`, различение обычных/сводных протоколов, подбор нормативных документов оценки, пропуск оборудования при `fgis_state=2`.
- Реализована связь справочников с прежней трёхпроходной процедурой метода измерения `methods.py:bind_methods_from_catalog`. При отсутствии таблиц или связей ID не подставляется автоматически.
- Добавлена самостоятельная команда диагностики `python -m att51_fsa inspect-resources`; отчёт остаётся локальным, может включать персональные данные, не публиковать в открытом GitHub.
- **69 автоматических испытаний** (с искусственными ресурсами и исходной XSD) пройдены на Linux: [Actions #37871192950](https://github.com/lvlaksim1/att51/actions/runs/37871192950). Чтение реальной установочной MDB в Windows проверяется отдельно в том же запуске. Предыдущий Windows-run подтвердил чтение по ADO/Jet и MSXML.
- Окончательная выдача `fsa_prot.xml` всё ещё отключена: реальные заполненные справочники, полная методология остальных факторов, обязательные поля структуры ФСА и эталонное сравнение пока не завершены.

Полный отчёт об исходных таблицах и цепочках: [FSA_RESOURCE_MAPPING.md](FSA_RESOURCE_MAPPING.md).
