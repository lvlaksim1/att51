# Проверка достаточности сведений для итогового XML ФГИС ФСА

**Дата:** 09.10.2026. **Основание:** схема `extracted/app/fileProtocolLoad_v4.xsd`, код `fsa_xml_module/att51_fsa/writer.py`, `desktop/whole_base_reports.py`, оригинальная цепочка по `research/FGIS_FSA_XML_PIPELINE.md` и конфиденциальный локальный отчёт владельца из Att51_export v0.1.8. Сам отчёт, рабочие пути, имена, исходные измерения, GUID и персональные идентификаторы здесь **не воспроизводятся**.

## Заключение

**Исходные данные достаточны для предметного исследования пяти внутренних XML-протоколов, но не доказана достаточность для корректного рабочего `fsa_prot.xml` и его приёма ФГИС.**

Полевой отчёт содержит 5 записей `SOUT_FACTORS` и 5/5 успешно прочитанных внутренних XML: **четыре фактора 13** (тяжесть) и **один фактор 14** (напряжённость). У всех есть `Document/@num_doc`, `@sign_date`, `factor/@izm_date`, исходные `izm_data` с `fact/norm/kut`, `nd_data`, ссылки на приборы и персонал. В тяжести встречается `count_params2`; в напряжённости этот узел отсутствует. Присутствуют сырые данные `boss`, которые необходимо отдельно обработать как роль подписанта. Номер и название РМ не распознаны во всех пяти блоках. Числовых соответствий приборов и людей ФГИС нет. Отсутствие этих полей **в TXT** не доказывает их отсутствия в иных таблицах MDB или пользовательских настройках.

## Карта обязательных и условных элементов XSD

| Путь в конечном XML | Требование XSD | Подтверждённый источник / дефицит |
|---|---|---|
| `protocol/DocId` | обязательная строка | `Document/@num_doc` есть у 5/5; проверить точное правило VBA |
| `DocCreationDate` | обязательная `xs:date` | `@sign_date` есть, но не доказано тождество дате документа |
| `DocStartDate` и `DocValidityDate` | обе обязательные `xs:date` | `factor/@izm_date` и `SOUT_FACTORS.izm_date` есть; полные интервалы и правила выбора не доказаны |
| `DataStatusId`, `ProtocolStatusId` | обязательные `xs:int` | нет подтверждённой числовой карты исходного статуса на реальные значения |
| `ApplicationDate` | обязательная `xs:date` | в пяти внутренних XML не обнаружена; искать в основной MDB и VBA |
| `Customer/CustomerKindId` | обязательный `xs:byte`; сведения о заказчике частично условные | отсутствует как готовый узел во внутренних XML; искать в `struct_org`, параметрах организации и оригинальных правилах |
| `ObjectInfo/TypeObjectId` | обязательный `xs:int` | без проверенного соответствия объекту, не подставлять внутренний `rm_id` |
| `ObjectInfo/FullNameObject` | обязательная строка | полное имя объекта требует исходной семантики; номер/название РМ в текущем отчёте не определены |
| `ObjectInfo/IsLab`, `IsAnotherDoc` | обязательные `xs:boolean` | получить условия оригинала; не проставлять необоснованные постоянные значения |
| `ObjectInfo/ResearchObject` | формально необязателен по XSD; вложенные `ResearchObjectInfo` обязательны, если блок есть | измерения имеются; преобразования факторов 13/14 не реализованы и не проверены |
| `ResearchObjectInfo/IndicatorId`, `Directory`, `FactValue`, `DocNameId` | обязательные, когда есть `ResearchObjectInfo` | сырые `fact/norm/kut` не эквивалентны этим полям; нужны правила `get_ResearchObjects2025` и справочники |
| `Equipment/EquipmentDetails/EquipmentId` | сам блок условный; каждый ID — `xs:unsignedLong` | есть GUID и заводские номера, но нет сопоставленных числовых ID ФГИС. Сырые GUID сюда не помещаются |
| `ApprovedUser/ApprovedUserDetails/idFullName` | блок условный; каждый ID — `xs:int` | есть `persons` и `boss`, но сопоставления и роли не подтверждены |
| `ObjectInfo/MethodDocId` и `AnotherDoc` | условные | имена НД есть; для ID нужен проверенный справочник `DIC_ND`, для уникальных методов — специальные правила |
| `Address`, `ProtocolScan` | условные | возможны другие таблицы/настройки и DOCX/PDF; режимы и условия оригинала требуют проверки |

**Важное разграничение:** обязательность XSD — только синтаксический уровень. Фактические бизнес-правила ФГИС могут требовать сведения, условные в XSD. Нельзя утверждать, что документ, прошедший XSD, обязательно будет принят порталом.

## Отдельные технические блокировки

1. `desktop/whole_base_reports.py` вычисляет номер/название РМ эвристическим перебором названий колонок `STRUCT_RM`, а не по подтверждённой реальной схеме. Все пять полевых записей без номера и названия. Проверить фактические колонки и связанные таблицы в режиме только чтения; не назначать произвольные значения.
2. Для имеющихся приборов нельзя ставить `NoEquipmentInfo=true` только потому, что их ID ФГИС не найдены: значение означает, что сведения об оборудовании не предусмотрены / оборудование не применялось.
3. `fgis_ra.ini` не найден; это не блокировка для чтения протоколов, но могут отсутствовать пользовательские переопределения методов/показателей. Нельзя автоматически создавать или подменять INI.
4. Модуль `writer.serialize_protocols` блокирует реальный вывод, разрешая только `synthetic_test_mode=True`; шесть перенесённых ранее факторных ветвей не включают 13/14. Диагностический TXT не является рабочим XML.
5. Не выполнены сравнение с выгрузкой исходной программы на одинаковых данных и контроль реального приёма принимающей системой.

## Последовательность продолжения задачи #2

1. Определить **точную** схему `STRUCT_RM`, включая связанные поля номера/названия; проверить достаточность сведений `struct_org`, `SOUT_FACTORS` и организационных таблиц. Сохранять исходные данные только локально.
2. Для каждого обязательного поля XSD составить трассу «таблица/внутренний XPath → оригинальная VBA-функция → преобразование → конечный XPath» и явно отделить найденные значения от невыясненных.
3. Перенести VBA `v52_exp_fgis_ra2025.get_ResearchObjects2025` именно для факторов 13 и 14, включая `izm_data`, `count_params2`, правила НД/методик, роль `boss` и особенности измерений.
4. Проверить источник `res_orgs.mdb` по оригинальной `[DB_res]`, сопоставления `FGIS_RA` и таблицы ресурсов. При отсутствии идентификаторов — сохранять сырые значения в **локальном отчёте об ошибках**, не вставляя несовместимые GUID в числовые поля конечной XSD.
5. Сборка итогового XML допустима только после проверки всех необходимых реквизитов, оригинальной логики, XSD и эталонного сопоставления. При нехватке данных — понятный перечень блокировок, без выдуманных значений.
6. Вся следующая правка Att51_export завершается полноценным опубликованным и проверенным Windows выпуском `Setup` + `Update` согласно мандату владельца.
