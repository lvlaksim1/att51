# Независимое восстановление `ResearchObjectInfo` для XML ФГИС ФСА

**Дата исследования:** 09.10.2026. **Подлинный источник:** VBA, извлечённые из `extracted/app/Attestation51.dot` версии 5.1.1739, и исходная `extracted/app/fileProtocolLoad_v4.xsd`. Сторонний `sout-app` не использовался.

## Что добавлено в модуль

Новые файлы `fsa_xml_module/att51_fsa/research_objects.py` и `pipeline_2025.py` воспроизводят проверяемое подмножество оригинальной цепочки:

1. Исходный внутренний `Document` из папки рабочего места → выбор `facid` → выделение `ResearchObjectDraft` через факторные процедуры `measurements.py`.
2. `Document/nd_data/nd` → отбор документов с назначением методики (`action="1"` и другие исходные признаки «изм») → `MethodCandidate`.
3. `ResourceCatalog` (`res_orgs.mdb`) → `DIC_ND`, `DIC_ND_INFO`, `DIC_ND_OA_METHODS` → трёхпроходный `get_DocNameId` и индивидуальный метод ОА, если у НД есть запись для конкретного показателя.
4. Рабочий `fgis_ra.ini` → подмена идентификатора измерения из `[Measurements]`, индивидуальная подмена показателя из `[vars_fiz<Directory>~<IndicatorId>]` по `DocNameId`. Для химии предусмотрена отдельная форма `[vars<him_id>]`, но сами химические ветви пока не перенесены.
5. Формирование полей `ResearchObjectInfo` в строгом порядке оригинального `save_XML`; проверка испытательного документа по `fileProtocolLoad_v4.xsd`.

### Шесть перенесённых разновидностей факторов

| `facid` | Исходная процедура VBA | Новый код |
|---|---|---|
| `4` | `read_ekv_shum_param` | Шум, обычные/эквивалентные измерения |
| `5` | `read_ekv_infr_param` | Инфразвук, обычные/эквивалентные измерения |
| `6` | `read_ultr_params` | Ультразвук, различие протокола образца 2019 года и прежней формы |
| `11` | `read_micro_params` | Микроклимат: температура, влажность, скорость, ТНС, тепловое облучение, экспозиционная доза |
| `12` | `read_osv_params` | Освещённость и коэффициент пульсации |
| `10099` | `read_aeroion_params` | Аэроионы положительной и отрицательной полярности |

Измеренные значения сохраняются в первоначальном текстовом виде, включая исходные разделители и обозначение неопределённости. Там, где исходный VBA разрешает пропуски/нулевые значения, условия перенесены раздельно по фактору.

### Блок `ResearchObjectInfo`: порядок по XSD и исходному VBA

```
ObjectInfo
  TypeObjectId
  MethodDocId [0..n]
  FullNameObject
  ResearchObject [0..1]
    ResearchObjectInfo [1..n]
      IndicatorId
      UniqueIndicator
      Directory
      FactValue
      MeasurementId
      UniqueMeasurement [0..1]
      DocNameId
      UniqueMethod [0..1]
      DocNameMethodikId [0..1]
      UniqueMethodik [0..1]
  IsLab
  IsAnotherDoc
```

Обозначения справочников: исходный `get_dic_name("1") = "DM-53535"`, `get_dic_name("2") = "DM-55254"`. Неизвестные справочники и неправильные индивидуальные переназначения помечаются ошибкой до формирования итоговых полей.

Нормативная методика: `DocNameId` берётся из `DIC_ND_INFO.dop2`. Если нормативного идентификатора нет, исходная ветвь допускает `UniqueMethod`. Метод ОА берётся из `dop5`, а если для текущего показателя указан уточнённый метод в `DIC_ND_OA_METHODS`, он применяется вместо общего `dop5`. Запись идентификатора в фигурных скобках выделяется по процедуре `get_method_oa_id`: результат помещается в `DocNameMethodikId`; иначе текст попадает в `UniqueMethodik`.

### Настройки исходной программы, которые ещё необходимо перенести полностью

- Пользовательские справочники `v52_exp_fgis_ra_dic.get_user_izm_param` и `v52_exp_fgis_ra_syn3.get_param/get_matter/get_measurement`, включая имена уникальных показателей.
- Полные приоритеты и особые методики `GetOAMethod` для всех факторов. Сейчас перенесены коды методов ОА только для уже исследованных физических показателей и часть связанных исторических кодов. Неизвестным показателям **не назначается произвольный метод**.
- Контроль диапазонов области аккредитации `get_oa_error`, дополнительная настройка `chk_method_rpelace` и все исключения исходного интерфейса.
- Персонал/подписи `ApprovedUser`, адреса и заказчики в их полной исходной семантике, сводные XML и другие обязательные блоки.
- Химические факторы, вибрация, ЭМП, тяжесть/напряжённость, радиация, лазерные факторы и другие неперенесённые ветви.

## Новый режим диагностики

Без Microsoft Word, без запуска исходной «Аттестации» и без изменения рабочей MDB:

```powershell
cd fsa_xml_module
python -m att51_fsa inspect-2025 --xml "D:\\Data\\ARMv51_files\\RM\\xml\\Protocol.xml" --resources "D:\\Data\\res_orgs.mdb" --fgis-ini "D:\\Attestation51\\fgis_ra.ini" --uncertainty --output "D:\\Temp\\research_2025.json"
```

Флаги `--acoustic`, `--acoustic-only`, `--per-operation`, `--micro-results`, `--micro-dose` соответствуют отдельным переключателям оригинала. Результат: перечень полей с их исходными путями, применёнными правилами сопоставления и списком недостающих данных. В отчёте принудительно установлен `not_exportable: true`.

**Внимание:** отчёты и ресурсные MDB могут содержать персональные данные лаборатории, поэтому их нельзя без очистки загружать в публичный репозиторий.

## Проверка

- Сборка и **98 автоматических испытаний на искусственных данных** (в том числе проверка настоящей XSD, условия всех шести факторов, выбор методики и содержательные подмены): [GitHub Actions #37872417247](https://github.com/lvlaksim1/att51/actions/runs/37872417247) — этап автоматических испытаний пройден.
- Предыдущая сквозная проверка на Windows подтвердила доступ к оригинальным образцовым `ARMv51.MDB`/`res_orgs.mdb` через ADO/Jet и XSD через MSXML 6.0. Windows-проверка образцовых файлов не подменяет испытания на заполненной базе.

**Статус:** `ResearchObjectInfo` умеет строиться на проверенных промежуточных данных; полный **рабочий** `fsa_prot.xml` всё ещё не формируется. До сравнения с результатом оригинальной программы на одинаковой заполненной базе объявлять полную эквивалентность нельзя.
