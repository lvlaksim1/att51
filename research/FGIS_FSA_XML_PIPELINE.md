# Формирование XML для ФГИС ФСА / ФГИС РА — установленная цепочка

**Дата исследования:** 09.10.2026. **Источник:** исключительно оригинальные файлы «Аттестация-5.1 (СОУТ)» версии 5.1.1739 из `extracted/`. Сторонний проект `sout-app` **не использовался**, согласно указанию владельца.

**Метод:** статическое чтение извлечённых VBA-модулей основной надстройки `extracted/app/Attestation51.dot` и штатной схемы `extracted/app/fileProtocolLoad_v4.xsd`. Работа программы в Windows, фактический экспорт и проверка файла через портал ФСА **не выполнялись**.

> В исходниках пользовательский раздел называется «ФГИС РА»; здесь он рассматривается в рамках интересующей владельца выгрузки в ФГИС Росаккредитации (ФСА). Это **не** выгрузка в ФГИС СОУТ.

## 1. Ключевое разделение — два XML

1. **Внутренний XML измерительного протокола** формируется при отдельной команде сохранения/отправки Word-протокола в базу рабочих мест. Код: `v51_savedoc.send_to_base_rm`, `v51_savedoc.save_XML` (старый путь), `v51_savedoc2019.SaveXML2019` → `DocApiXMLDocCls.CreateXMLDocument` → `DocApiXMLDocCls.ReadData` → `DocApiXMLDocCls.SaveXMLDocument`. Источник данных — сведения `ActiveDocument`, переменные, закладки, таблицы документа; XML записывается рядом с документом в каталоге `xml/` соответствующего РМ. Внутренний XML содержит `Document`, `factor`, `si_guids`, `persons`, `nd_data`, `izm_data` и др.
2. **Итоговый XML Росаккредитации** позднее формируется формой `v52_exp_fgis_ra`. Она читает уже **сохранённые** внутренние XML, выбирает протоколы из главной базы и связывает их с дополнительными справочниками, преобразует поля и создаёт новый документ `<root><protocol>...</protocol></root>`. По умолчанию файл называется `fsa_prot.xml`. При превышении лимита формируются `fsa_prot1.xml`, `fsa_prot2.xml` и т. д.

Следствие: **обычное сохранение DOC/DOCX и специальная передача в базу РМ не эквивалентны**. Если внутренний XML не создан/устарел, экспорт может не учитывать недавние изменения Word.

## 2. Источники данных

|---|---|---|
| **Основная рабочая MDB** (`ARMv51.MDB` как образец, рабочая база выбирается пользователем) | `v5_attest_DB.main_DB`, запрос к `sout_factors`, `struct_org` | ID рабочих мест и факторов, перечень протоколов, их относительные пути, сведения о заказчиках, даты |

| **Сводные XML** `<папка БД>_files/000_org_data/<GUID организации>/sv_docs/<имя>.xml` | `v52_exp_fgis_ra.read_sv_prots`, `get_xml_data_sv` и ссылки `Document/prot_xmls/prot_xml` на первичные XML | Данные сводного протокола, связь с измерениями отдельных РМ |

| **Рабочие настройки `options.ini`, `fgis_ra.ini`** | `System.PrivateProfileString(path_attest_folder + "\\fgis_ra.ini", ...)` и секции `[fgis_ra]` в `options.ini` | Выбранные режимы, сопоставления отдельных показателей и методов, адреса, исключения, параметры экспорта. ## 3. Выбор перечня выгружаемых протоколов

Вход из дерева организации: `v51_org_tree.prot_info_btn_Click` → `v52_exp_fgis_ra.read` и форма экспорта.

### Режим А — из протоколов отдельных рабочих мест (`chk_sv_prot=False`)

`v52_exp_fgis_ra.fill_fgis_ra_data(False)` выполняет:

1. Создание дерева РМ через `fill_sout_tree_structure`, учёт фильтра региона/подразделений.
2. По каждому РМ чтение:
   `SELECT * FROM sout_factors WHERE rm_id=<...> AND ... ORDER BY factor_id`;
   код исключает часть `factor_id` и может применять дополнительные пользовательские фильтры.
3. Поле `sout_factors.file` трактуется как путь к DOC/DOCX **относительно** `v5_attest_DB.main_fs_path`.
4. `doc_to_xml2` строит соседний XML: `dirname(doc)\\xml\\basename(doc).xml`.
5. Только если XML существует и тип фактора поддержан, вызывает `FillPrototcolData(..., is_sv_prot=False)`. Отсутствующие XML не заменяются автоматическим перечитыванием документа Word этим кодом.

### Режим Б — из сводных протоколов (`chk_sv_prot=True`)

`read_sv_prots`:

1. Получает GUID организации из `struct_org.mguid`.
2. Открывает `main_fs_path\\000_org_data\\<GUID организации>\\docs_list.xml`.
3. Выбирает записи `Document/doc` с `doc_type="3"` (сводный протокол), применяет фильтры; DOC/DOCX и XML ожидаются в `sv_docs/`.
4. `get_xml_data_sv` читает сводный XML, а для результатов измерений следует ссылкам `Document/prot_xmls/prot_xml[@file]` на XML отдельных РМ. В коде предусмотрено предупреждение о нарушении ссылочной целостности таких ссылок.

## 4. Преобразование и сопоставление сведений

`FillPrototcolData` строит промежуточный объект `fgis_ra_prot_cls` для каждого протокола. Данные не передаются в окончательный XML «как есть».

- **Реквизиты:** `get_xml_data` читает `Document/@num_doc`, `@fill_date`, `@sign_date`, `@fgis_state`, `factor/@izm_date` и `@facid`. Флаг `fgis_state="1"` возвращает `no_exp` — исключение протокола из дальнейшего пути.
- **Средства измерения:** `Document/factor/si_guids/si_guid[@guid,@num]`, опционально `si_guids_os` и `si_guids_dop`, сопоставляются `v5_res_main.get_si_by_num` с ресурсным справочником. Далее `FGIS_RA` содержит связи вида `rec_type=0, rec_guid=<GUID средства>, IntValue=<числовой ID ФГИС>`.
- **Сотрудники:** из узлов `persons`, `exp_persons`, `boss`, затем `ATT_PERSON`, далее соответствия `FGIS_RA` с `rec_type=1`. Предусмотрена обработка ролей и отсутствие сопоставления.
- **Нормативные документы:** внутренние `nd_data/nd` сверяются с `DIC_ND`, `DIC_ND_INFO`, `DIC_ND_SYN`, `DIC_ND_OA_METHODS` через `v5_options_dic.get_nd_by_name`. Если наименование не найдено в ресурсах, код выводит предупреждение «Выгрузка невозможна». Для некоторых документов без числовой привязки предусмотрено представление «иной НД» / `AnotherDoc`, для методик — `UniqueMethod` и `UniqueMethodik`.
- **Измеренные значения:** `v52_exp_fgis_ra2025.get_ResearchObjects2025` выбирает ветку по фактору и читает атрибуты исходных `izm_data`, например `fact`, `U095`. Программа переводит исходные записи в `ResearchObject` с идентификаторами `IndicatorId`, `MeasurementId`, `DocNameId`, `FactValue`, `Directory` и др. Это **преобразование результатов**, а не доказательство полного повторного расчёта оценки рабочего места.

**Пример, шум:** в одной из ветвей код читает `Document/izm_data/Level[@bm='Lekv']/@fact` и задаёт `IndicatorId="3472"`, `MeasurementId="650"` (значение в дБА). В другом режиме подробных измерений используются другие узлы и идентификаторы. Значит, результат зависит не только от фактора, но и от параметров/версии экспорта.

## 5. Создание итогового `fsa_prot.xml`

Функция `v52_exp_fgis_ra.save_btn_Click` проверяет наличие подготовленных `FgisRaProtocols`. По умолчанию помещает **до 100 протоколов на файл**; при превышении разбивает выгрузку на несколько XML.

`v52_exp_fgis_ra.save_XML` через `MSXML2.DOMDocument` создаёт:

```xml
<?xml version="1.0" encoding="utf-8"?>
<root>
  <protocol>
    <DocId>...</DocId>
    <DocCreationDate>...</DocCreationDate>
    <DocStartDate>...</DocStartDate>
    <DocValidityDate>...</DocValidityDate>
    <DataStatusId>...</DataStatusId>
    <ProtocolStatusId>...</ProtocolStatusId>
    <Customer>...</Customer>
    <Equipment>...</Equipment>
    <ApprovedUser>...</ApprovedUser>
    <ObjectInfo>...</ObjectInfo>
  </protocol>
</root>
```

**Условная иллюстрация структуры, не реальный выгруженный файл:** фактические вложенные узлы, их обязательность, порядок и содержание определяются XSD и выбранными настройками; `ProtocolScan` (содержимое DOCX/PDF в Base64), `ResearchObject` и `MethodDocId` входят в соответствующие части дерева при наличии данных.

После `curxmldoc.Save xml_path` выполняется локальная проверка по **`extracted/app/fileProtocolLoad_v4.xsd`** через `MSXML2.XMLSchemaCache.6.0` и `xmlDoc.Validate`, если файл схемы есть и не включено предусмотренное условиями отключение проверки. Наличие отдельного `extracted/app/fgis_ra/fsa_v02.xsd` не делает его схемой этого пути.

В изученной цепочке выход — **локальный файл XML**, сохранённый через диалог выбора пути. Непосредственная отправка на сервер ФСА в этих процедурах **не обнаружена**: факт загрузки через портал нельзя приписывать самой функции.

## 6. Особые случаи и выявленная проблема

1. **XML протокола отсутствует:** в режиме отдельных РМ экспортёр проверяет существование и не вызывает создание XML из текущего документа; протокол может не включиться.
2. **НД не распознан:** формируется ошибка «Выгрузка невозможна», требуется уточнение имени/синонима в ресурсах.
3. **Не найдены сопоставления приборов/сотрудников:** появляются предупреждения и неполные идентификаторы. Полное условие блокирования зависит от режима и ветки кода, требует отдельного разбора.
4. **Сводный протокол с повреждёнными ссылками:** отдельный отчёт о нарушении ссылочной целостности.
5. **Скан протокола:** при выборе DOCX или PDF содержимое добавляется через Base64, существенно увеличивая XML.
6. **Предварительно обнаруженное несоответствие кода XSD:** `save_XML` при выбранных статусах пишет `DataStatusId="13 - Отправлен"`, `DataStatusId="20 - Черновик"` и `ProtocolStatusId="6 - Действует"`, а `fileProtocolLoad_v4.xsd` объявляет **оба элемента как `xs:int`**. Если эта ветка реально исполняется и XML проверяется указанной схемой без преобразования значений, будет несоответствие типа. Это **статически подтверждённый конфликт**, но не доказанная фактическая ошибка рабочего запуска. Нужен тест одного малого искусственного протокола и проверка конкретной ветки.

## 7. Что сохранить для воспроизведения существующей выгрузки

- Рабочий файл базы РМ (его имя не обязательно `ARMv51.MDB`) **вместе** с соответствующим каталогом `*_files` и всей вложенной структурой `xml/`, `000_org_data/`.
- Актуальный **рабочий** `res_orgs.mdb` с заполненной таблицей `FGIS_RA`, а не только пустой справочник из установщика.
- Актуальные **рабочие** `options.ini`, `fgis_ra.ini` и доп. сведения об организации.
- Если выгружаются приложения — соответствующие DOC/DOCX/PDF и их имена.
- `fileProtocolLoad_v4.xsd` и исполняемые VBA для воспроизводимой трассировки.
