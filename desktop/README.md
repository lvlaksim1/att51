# Att51_export — приложение для Windows

**Состояние: диагностическая версия.** Исходные базы, протоколы и справочники «Аттестации-5.1» читаются без Word. Полный XML для ФГИС ФСА пока не готов — в программе нет кнопки выдачи рабочего `fsa_prot.xml`.

## Строгие правила установки

- Папка установки: **`%ProgramData%\Att51_export`** (обычно `C:\ProgramData\Att51_export`), а не `Program Files`.
- Исполняемый файл, зависимости, XSD, значок и загруженные обновления хранятся только внутри `Att51_export`. При работе приложение не создаёт отдельные журналы или настройки в профиле пользователя.
- Исходные MDB/XML/INI могут находиться в других папках, но **не копируются и не изменяются**. Они используются только для чтения по указанным пользователем путям.
- В каждом релизе GitHub: `Att51_export_Setup_vX.Y.Z.exe` — первая установка; `Att51_export_Update_vX.Y.Z.exe` — обновление установленной программы.
- Полный установщик предлагает необязательный ярлык на рабочем столе и создаёт пункт меню «Пуск». Ярлыки и стандартная системная регистрация установленной программы — исключения, необходимые самой Windows.
- Приложение самостоятельно проверяет последний выпуск GitHub. При наличии новой версии сверяет SHA-256 и размер файла, запрашивает повышение прав только для обновления, скачивает файл в `Att51_export\updates` и запускает установщик. Если контрольная сумма GitHub отсутствует, автоматическое обновление не запускается.
- Удаление: «Установленные приложения» Windows либо `%ProgramData%\Att51_export\unins000.exe`; вместе с приложением удаляются собственные файлы обновления, а рабочие базы пользователя не затрагиваются.
- Значок программы, ярлыка и установщика: документ с зелёной стрелкой и словом **EXPORT** — без надписи XML.

## Обнаружение исходных файлов (задача № 8)

Начиная с v0.1.1 приложение проверяет известные каталоги оригинальной «Аттестации-5.1» внутри `Program Files` / `Program Files (x86)` и путь из `ATT51_ORIGINAL_DIR`. Следующее исправление дополнительно читает зарегистрированный Windows путь удаления оригинала, проверяет одноимённые/переименованные каталоги непосредственно внутри `Program Files` (без обхода дисков) и учитывает перенаправление старых 32-разрядных настроек Windows в `%LOCALAPPDATA%\VirtualStore`. Ничего в реестре и оригинальных файлах не изменяется. Оригинальная установка распознаётся по наличию **обоих** файлов `Attestation51.dot` и `options.ini`. Произвольные каталоги пользователя и диски не сканируются.

- Рабочая база определяется по `[DB] sout_path` в рабочем `options.ini`; если Windows создала пользовательский `VirtualStore`, он имеет приоритет над заводским вариантом в каталоге программы. Формат исходного INI допускает строки без `=` в других секциях. Если значение указывает на каталог с несколькими MDB, необходим явный выбор. В чистом установочном `options.ini` может вообще не быть `[DB]`: в таком случае путь автоматически восстановить из установщика нельзя.
- Ресурсная база выбирается по `[DB_res] res_flag/res_path`; при `res_flag=1` недоступный внешний файл **нельзя** заменять локальным. При локальном режиме учитывается рабочая пользовательская копия `res_orgs.mdb` из `VirtualStore` (если присутствует); иначе используется файл оригинальной установки.
- Параметры `fgis_ra.ini` ищутся в подтверждённой исходной установке с приоритетом рабочей пользовательской копии из `VirtualStore`, не в каталоге Att51_export. Файл может отсутствовать до использования соответствующих функций оригинала.
- **Для проверки всех протоколов отдельный XML не нужен.** Источник перечня — выбранная рабочая MDB, содержащая `sout_factors.file`; программа определяет путь внутреннего XML для каждого документа из связанного каталога `<имя MDB>_files`. «Проверить протоколы базы» перечисляет и отсутствующие XML, «Сопоставить все XML (6 факторов)» проводит независимую частичную проверку существующих XML, не требуя выбрать один файл. При наличии фильтра по ID РМ ограничивается им. Последняя операция охватывает только шесть уже исследованных видов факторов, не формирует рабочий файл ФГИС.
- Поле «XML для отдельной проверки» находится в необязательном разделе диагностики. Кнопка «Выбрать из базы…» читает путь из `sout_factors.file` и предлагает выбор при нескольких протоколах. Только команды «Сопоставить один XML» и «Проверить один XML по XSD» требуют этот файл.
- `fgis_ra.ini` **не обязателен для перечисления протоколов**. В оригинальных макросах он хранит пользовательские подмены идентификаторов измерений и методов: `[Measurements]`, `[vars_fiz...]`, `[vars...]`. Если отсутствует, оставьте поле пустым; в отчёте будет предупреждение о неполноте пользовательских сопоставлений. Пустой файл не создавать.
- Если оригинал в другом каталоге, доступна кнопка «Указать папку Аттестации…». Основные исходные поля — две MDB; дополнительные INI и XML относятся к настройкам/проверке отдельных протоколов. Данные не копируются и не изменяются, найденные пути не записываются в настройки приложения.

Важно: обнаружение файла не доказывает актуальность его содержимого и соответствие рабочей базе. Достоверность экспорта в ФГИС пока не установлена; кнопка полноценной выгрузки остаётся недоступной.

## Сборка и проверки

Windows, **32-разрядный Python 3.11** для совместимости с Jet OLE DB 4.0, Inno Setup 6:

```powershell
python -m pip install -r desktop/requirements-build.txt
./desktop/build.ps1 -Version 0.1.0
```

Проверить тесты: `python -m unittest discover -s desktop/tests -v`.

Рабочий процесс выпуска — `Att51_export Windows Release` в GitHub Actions. Его можно запустить вручную с номером версии или открыть от имени владельца задачу с заголовком `[ATT51_BUILD_RELEASE]` и телом `{"version":"0.1.0"}`. Перед публикацией выполняются автоматические испытания, сборка приложения и обоих установщиков, пробная установка/обновление/удаление на Windows. После создания релиза удаляются старые выпуски, сохраняя только последний.

**До проверки на заполненной рабочей базе и сравнения с оригинальным экспортёром функционал создания полного XML остаётся заблокированным.**

## Разделение общей и индивидуальной диагностики

Пакетная операция использует единую ресурсную базу и последовательно обрабатывает XML из рабочей MDB, выводя номер РМ, тип фактора, источник XML, состояние, ошибки и сводные количества. Неподдерживаемые факторы помечаются явно, а повреждённый XML не обрывает просмотр остальных записей. Отсутствующие XML видны в отдельной проверке базы. Это не полноценная выгрузка ФГИС, работающая на всех факторах: отдельное разрешение потребуется после завершения переноса и проверки эквивалентности.

## Чтение MDB при ошибке блокировки Access (после v0.1.3)

Если Jet/ACE сообщает «Блокировка файла невозможна», причина может быть в отсутствии возможности создать служебный `.ldb` в каталоге исходной MDB либо в совместном использовании сетевого диска. При работе с сетевой MDB приложение **не открывает её движком Access напрямую**: сначала создаёт временную копию в `%ProgramData%\\Att51_export\\data`, читает её через Jet/ACE с совместным доступом только для чтения, затем закрывает подключение и удаляет копию. При аналогичной ошибке локального файла выполняется такой же запасной путь. Программа не создаёт копий в каталоге оригинальной базы и не возвращает в него изменения.

Перед копированием и после него проверяются размер и время последнего изменения исходной MDB; если они изменились, диагностика останавливается. Это не полноценная согласованная резервная копия: одновременно изменяемый оригинал может быть непригоден для точного снимка, даже если эти свойства не изменились. Для контрольных результатов желательно завершить операции записи в базу. **Полная рабочая выгрузка XML ФГИС по-прежнему запрещена** до проверки исходного алгоритма на обезличенных данных.

Снимок создаётся и удаляется только во внутренней папке приложения, доступной для чтения текущему пользователю; создание, копирование и удаление не требуют прав записи на сетевой диск с оригиналом. В отчёте проверки базы указывается, когда был использован локальный снимок. При неудаче удаления локальной копии выдаётся ошибка с её точным расположением.

## Различие внутреннего XML и итогового XML ФГИС

Внутренний XML «Аттестации-5.1» имеет корневой элемент `Document` и вложенные сведения `factor`. Схема `fileProtocolLoad_v4.xsd` определяет **другой документ**: формат итоговой выгрузки ФГИС. Проверять исходный `Document` по этой схеме нельзя: сообщение «Document не объявлен в схеме» ожидаемо и само по себе не означает повреждения исходного протокола.

В интерфейсе команда «Проверить структуру XML» проверяет синтаксис исходного внутреннего XML и наличие обязательных для чтения `Document/factor/facid`, а также выводит сведения протокола. Проверка **не подтверждает** возможность готовой выгрузки. Факторы 13 (тяжесть) и 14 (напряжённость) распознаются как корректные исходные документы, однако преобразование их измерений для ФГИС ещё не реализовано.

Если выбранная `res_orgs.mdb` не содержит ни приборов, ни сотрудников, ни таблицы `FGIS_RA`, диагностика предупреждает, что возможен выбор исходного шаблона вместо рабочей ресурсной базы. Автоматически заменять ресурсный источник предположением о его расположении запрещено.

## Контроль компонента win32timezone в Windows-сборке

PyInstaller явно включает `win32timezone` и pywin32. Контроль установленной программы теперь не ограничивается проверкой значка и версии: он загружает модули COM/ADO в самом исполняемом файле и отдельно открывает для чтения эталонный `extracted/app/model/ARMv51.MDB`. Сборка и публикация прекращаются, если эти испытания завершаются ошибкой. Исходный образец MDB не включается в установщик.
