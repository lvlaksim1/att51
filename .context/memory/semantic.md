## Не повышать до подтверждённых фактов без проверки

- Техническая доступность третьего ПО в GitHub не доказывает права на его распространение.

## Механизм выгрузки ФГИС ФСА (проверенное длительно полезное знание)
- Программа имеет два разных XML: внутренний на РМ / сводный протокол и итоговый fsa_prot.xml. Итоговый собирается из рабочей MDB + её *_files/xml + res_orgs.mdb со связями FGIS_RA + рабочих настроек; выбранная XSD — fileProtocolLoad_v4.xsd. Источник: research/FGIS_FSA_XML_PIPELINE.md и VBA из Attestation51.dot; уровень: статическое чтение кода, без исполнения.
- Несовпадение генерации DataStatusId/ProtocolStatusId (число с текстовым названием) и xs:int — доказанное расхождение исходников, требующее теста его реального влияния.

## Решение владельца и архитектурная граница новой разработки
- Владелец подтвердил создание **самостоятельного программного модуля ФГИС ФСА**, работающего без Word/«Аттестация-5.1», при сохранении тех же рабочих Access MDB, XML, справочников, настроек и точных оригинальных преобразований. Источник: прямая директива владельца 09.10.2026; authority: owner directive. Это переопределяет ранее отложенную разработку замены, но **не** разрешает стороннюю переработку sout-app.
- Начат исходный код fsa_xml_module/; первые 10 тестов с исходной XSD успешны (Actions #37868240736), но реальные алгоритмы ещё не полностью перенесены и эквивалентность не доказана. Authority: GitHub source & CI. Контроль задач issue #2.

## Дополнительные проверенные факты — независимый модуль ФГИС ФСА
- Отбор протоколов реализован двумя путями: основная рабочая MDB/sout_factors и docs_list.xml/sv_docs. Выбранные РМ и подразделения передаются явно, поскольку UI-дерево оригинала не воспроизводится автоматически. Источник: fsa_xml_module/att51_fsa/selection.py, VBA, research/FSA_INDEPENDENT_MODULE_STATUS.md.
- Факторные ветви 4 (шум), 5 (инфразвук), 12 (свет) и три прохода метода (get_DocNameId) перенесены в промежуточные структуры и проверены синтетическими данными. Результат не является готовым XML. Источник: measurements.py, methods.py и GitHub Actions #37869915459.
- Нативный Windows Jet OLE DB 4.0 открыл образцы MDB, MSXML 6.0 проверяет штатную XSD. Источник: Actions #37868574234.
- Критерий готовности остаётся строгим: все ветви, реальные справочники и сравнение готового XML исходной программы. Без этого генерация заблокирована; authority: owner directive и verification evidence.


## Стабильное понимание оригинальных ресурсов ФГИС ФСА
- v5_res_main.get_si_by_num: сначала GUID прибора, затем заводской номер с цифрами; v52_exp_fgis_ra.get_pers_info: GUID сотрудника, затем СНИЛС с цифрами. FGIS_RA хранит числовые внешние ID для типов 0 (приборы), 1 (сотрудники), связка по rec_guid. Источник: оригинальный VBA в extracted/app/Attestation51.dot; независимые синтетические проверки ресурса в tests/test_resources.py; authority: статический код и проверяемые тесты.
- НД: хеш prot_api.get_nd_hash (цифры и пять русских гласных), поэтапное сопоставление v5_options_dic.get_nd_by_name с фактором/синонимами/коротким названием/точным именем; дополнительные MethodDocId=dop2, приоритет=dop4, OA-method=dop5. Источник: оригинальный VBA, research/FSA_RESOURCE_MAPPING.md.
- Установочная res_orgs.mdb **не имеет** таблиц FGIS_RA/DIC_ND_INFO/DIC_ND_SYN. Windows ADO OpenSchema проверено в Actions #37870387468. Для настоящего экспорта нужна **рабочая** ресурсная база, которую оригинал мог дополнить. Модуль намеренно не обновляет схемы.
- Новый ResourceCatalog и inspect-resources — независимое чтение источников без Word. Успешность 69 синтетических испытаний не является доказательством полной эквивалентности ФСА. Источник: GitHub CI #37871192950; authority: проверенный репозиторий.

## Правило автономного приложения Att51_export — 09.10.2026
- Папка строго C:\ProgramData\Att51_export (символическая %ProgramData%\Att51_export), не Program Files. Собственные данные и загружаемые обновления внутри неё, системные ярлыки/Windows uninstall metadata являются исключениями. В иконке EXPORT, не XML.
- Принцип MailRu Desktop: каждый GitHub Release имеет Att51_export_Setup_vX.Y.Z.exe и Att51_export_Update_vX.Y.Z.exe, встроенный GitHub-проверяющий обновитель и полноценный Inno Setup uninstaller, только последний релиз хранится.
- Первый релиз v0.1.0 прошёл GitHub Actions #37875093384: 98 испытаний ядра + 20 упаковки, Windows install→update→uninstall. Автоматическое обновление сверяет опубликованную SHA-256; при её отсутствии автозапуск заблокирован.
- Отдельная незавершённая задача — фактическая генерация полной ФГИС XML, текущая версия лишь диагностическая и не создаёт рабочую выгрузку. Источник: desktop/README.md, issue #2.


## Подтверждённые различия путей в Att51_export — 09.10.2026
- `desktop/installer/full.iss` и `update.iss` фиксируют **только** каталог программного обеспечения `%ProgramData%\Att51_export`. Это **не** местоположение оригинальных рабочих MDB, протокольных XML и `fgis_ra.ini`.
- `desktop/app.py` (v0.1.0) инициализирует все четыре поля MDB/resources/XML/INI пустыми. Владелец подтвердил, что в установленной версии эти поля показаны пустыми, и задал вопрос об их фиксированном пути. Задача [#8](https://github.com/lvlaksim1/att51/issues/8) — восстановить правила автоматического определения.
- По оригинальному конвейеру каталог `<имя MDB>_files` выводится из MDB (`sources.py:files_directory`), а `res_orgs.mdb` может находиться по общему пути из `options.ini/[DB_res]`. Внутренний XML определяется по выбранному протоколу, единого фиксированного файла у всех рабочих мест нет.
- Не считать вопрос о путях прямым приказом всегда копировать источники внутрь ProgramData; нельзя смешивать каталоги программы и оригинальных источников. Режим доступа к внешним MDB/XML/INI — только чтение. Статус: автоподстановка ещё не реализована.
