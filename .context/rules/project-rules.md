# Правила проекта att51

## Доказательность и исследование
- Основой исследования «Аттестация-5.1 (СОУТ)» являются только подлинные файлы из extracted/ и воспроизводимые результаты их изучения.
- По прямому указанию владельца от 09.10.2026 **пока не использовать сторонний проект sout-app** и не переносить в выводы его алгоритмы.
- Отделять статически подтверждённые исходным кодом действия от наблюдаемого поведения Windows-приложения. Не утверждать, что программа прошла испытание без реального теста.
- Не переписывать распакованные исходные файлы ради исследования. Запуск и запись в рабочие базы требуют согласованной контролируемой среды и копий.
- Поддерживать полную капсулу Project Manager с согласованной контрольной записью и явной памятью о проверенных решениях.

## Общение с владельцем
- Любое предложение, идея или техническое решение владельца рассматривается как гипотеза, а не как заведомо правильное указание по реализации.
- Менеджер критически оценивает предложения по проверенным данным, ограничениям, рискам и доступным альтернативам; выявленные ошибки и недостатки сообщает прямо.
- Полномочия владельца определяют цели и окончательные решения, но не превращают техническое предположение в доказанный факт.
- Оценки результатов консервативны. Состояния «не доказано», «неопределённо», «заблокировано» или «ошибка» указывать точно, не подменять успехом промежуточную проверку.
- Все объяснения давать на русском языке; избегать английских слов и англицизмов, если есть понятный русский эквивалент. Необходимые технические термины пояснять.

## Обязательный конечный результат разработки приложения — решение владельца 09.10.2026
- **Каждый цикл изменений приложения Att51_export должен заканчиваться готовой к загрузке парой установщиков**: `Att51_export_Setup_vX.Y.Z.exe` и `Att51_export_Update_vX.Y.Z.exe` в проверенном GitHub Release. Исходный код, отдельный коммит, пробная сборка и сообщение о готовности без установщика **не считаются выполнением** задачи разработки.
- На последовательные штатные выпуски приложения дано постоянное разрешение владельца; повторный запрос санкции на выпуск по каждой итерации не нужен. Эта норма заменяет только прежнее требование отдельного согласования **выпуска Att51_export**, прочие ограничения продолжают действовать.
- Перед передачей результата проверять: автоматические испытания, Windows сборку/полную установку/обновление/удаление, статус публикации GitHub Actions `success`, ровно два загруженных актива Release, ссылки на оба установщика. Сохранять только последний бинарный релиз.
- При ошибке выпуска не объявлять задачу завершённой, восстановить работоспособный выпуск либо явно зафиксировать препятствие. Обновлять капсулу фактическим статусом. Исходные рабочие базы и документы владельца не включать в релиз.

## Строгий запрет неподтверждённых значений — указание владельца 10.10.2026
- Ничего не додумывать для любого поля, идентификатора, метода, срока, типа объекта, единицы измерения, адреса или соответствия. Не угадывать из косвенных признаков и привычных стандартных значений.
- Любое значение имеет достоверный проверяемый источник. Если текст не установлен, указывать «НЕТ ДАННЫХ», даже когда числовой код известен.
- Обязательные отсутствующие данные для итогового XML блокируют формирование с указанием причины; не подменять их вымышленными. Excel не подставляет числовые коды ФГИС вместо текстовых обозначений.
