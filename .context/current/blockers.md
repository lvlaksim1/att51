# Ограничения, риски и незакрытые проверки

- Нет независимого запуска оригинального приложения в Windows/Word. Нельзя утверждать, что статическая последовательность вызовов полностью совпадает с наблюдаемыми окнами или всегда выполняется в указанном порядке.
- Для подтверждения деталей цикла необходимо воспроизводимое чтение/извлечение VBA: отчёт research/OPERATING_CYCLE.md есть, но выводы отдельных обработчиков должны быть сопоставлены с оригинальными модулями и сохранены с точными ссылками.
- Таблицы и связи всех MDB, расчёты всех факторов, исключительные сценарии сохранения, механизм действительной сетевой отправки в ФГИС пока полностью не подтверждены.
- Открытие старой базы может выполнять преобразование её структуры; исследования с запуском допускаются только на копиях и после согласования.
- Доступность всех файлов в публичном GitHub не доказывает прав правообладателя на распространение или работу продукта; решения об изменении публикации требуют отдельной оценки.
- В репозитории нет механизма, который превращает новую запись в капсулу или комментарий GitHub в исполняющийся экземпляр ИИ-менеджера. Вызов выполняется через прямое обращение владельца в чат с восстановлением менеджера по ENTRYPOINT; фоновую работу не подразумевать.
- **Снято прежнее препятствие:** неполнота extracted/ (2 отсутствующих файла). В GitHub сейчас все 3614 файлов, это не актуальный блокирующий фактор.

## Для независимого XML-модуля
- 39 автоматических проверок основаны преимущественно на искусственных данных. Подтверждено чтение **пустых образцовых** оригинальных MDB через Windows Jet/ADO; чтение заполненной рабочей базы и соответствие реальному экспорту ещё не проверены.
- Не перенесены все ветви исходного преобразователя VBA. Создание внешне правильного XML без этих ветвей потенциально приводит к содержательно неверной отчётности; выпуск рабочего экспорта заблокирован до покрытия функций и эталонного сравнения.
- Для проверки полной эквивалентности может потребоваться обезличенный набор реальных рабочих MDB+каталога *_files+res_orgs.mdb+рабочих ini и соответствующий XML, сгенерированный оригиналом. Без этого статус — частичная реализация, а не подтверждённая замена.


## Ограничения после этапа ресурсов
- Установочная res_orgs.mdb не содержит FGIS_RA, DIC_ND_INFO и синонимов; для проверки реальных соответствий нужна **рабочая заполненная** база, без неё невозможна проверка реальных FGIS ID и уникальных методик.
- Краткие названия сопоставляются ограниченным буквальным подмножеством VBA Like и помечаются для проверки. Полный перенос всех специальных шаблонов, режимов и специфичных методов остаётся открытым.
- Даже успешный синтетический XML по XSD не доказывает совпадения с результатом оригинальной программы. Рабочая генерация намеренно отключена; сравнение на одинаковых входных данных ещё не выполнено.

## Оставшиеся ограничения XML ФСА
- Шесть факторов — только часть исходного get_ResearchObjects2025; нет всех химических, вибрационных, электромагнитных и иных ветвей.
- Не выполнено полное восстановление Customer, Address, ApprovedUser, пользовательских справочников, всех фильтров исходной формы и сводных измерений.
- 98 синтетических тестов, включая XSD, не равны проверке на рабочей лабораторной базе. Эталонное сравнение ещё не выполнено.
- Рабочая генерация намеренно запрещена; не представлять корректную XSD как подтверждение правильности отчётности ФСА.

## Открытые ограничения после v0.1.0
- Выпущенная v0.1.0 — только диагностика; отсутствуют полное содержательное формирование ФГИС XML и его проверка на обезличенной рабочей базе против оригинала.
- Прямое обновление через интерфейс проверено алгоритмическими тестами и выпущенным кодом; полная установка/обновление/удаление проверены на Windows, но ручное взаимодействие пользователя с диалогами GUI пока не проверялось.
- При размещении в ProgramData не разрешать обычным пользователям записывать в каталог исполняемых файлов; будущие настройки/журналы должны быть внутри отдельной папки данных с ограниченными разрешениями.


## Разделение путей программы и источников — пользовательская проверка
- В v0.1.0 не реализовано автозаполнение исходных MDB, XML и INI: 4 поля GUI инициализируются пустыми значениями. Путь установки `%ProgramData%\Att51_export` **не гарантирует** расположения исходных файлов.
- Для точного автоматического обнаружения необходимо установить из исходных VBA и конфигураций, где оригинал хранит **текущую** MDB, где находится его собственный каталог и `fgis_ra.ini`, какая ресурсная база выбрана и какой внутренний XML относится к конкретному протоколу. Не использовать необоснованные жёсткие пути.
- Множественные MDB, внешний `res_orgs.mdb`, отсутствие оригинала или доступных настроек должны обрабатываться как отдельные случаи с резервным ручным выбором. Задача #8 ещё не реализована.

## После программной реализации автопутей (#8)
- Синтетическая и Windows-сборочная проверка прошли (#37876732456, #37876817897), но на компьютере владельца не проверено, что `options.ini` находится в ожидаемой оригинальной папке и что `sout_path` / `res_path` указывают на текущие заполненные MDB.
- Для нестандартного расположения оригинала требуется явное указание папки. При нескольких базах и XML выбор остаётся пользовательским; программа не должна выбирать произвольно.
- **Предыдущее препятствие выпуска снято:** владелец поручил продолжить, штатный выпуск v0.1.1 успешно завершился в Actions #37877636893. Последний публичный бинарный релиз — v0.1.1; оставшееся препятствие задачи #8 — проверка на реальной установке владельца.

## Оставшиеся ограничения обнаружения после новой реализации
- Выявленные ограничения разбора INI и поиска исходной установки программно устранены в main `1e4bcd1793f4a61afe0d84e51436077255680601` и прошли CI. Не доказано, что на пользовательском ПК именно UAC VirtualStore либо что там существует `[DB] sout_path`.
- Нет оснований заполнять пустые поля выдуманными или шаблонными путями: настоящая MDB может быть выбрана в другом каталоге, `fgis_ra.ini` может быть ещё не создан, XML выбирается по рабочему протоколу.
- Пока нет отдельно санкционированного релиза после v0.1.1, а пользовательское испытание исправлений не выполнено. Полная ФСА-выгрузка по-прежнему запрещена.

## После публикации v0.1.2
- Блокировка выпуска снята: в GitHub последний проверенный релиз v0.1.2, оба установщика опубликованы, Windows цикл успешно проверен (Actions #37879311246).
- Остаётся невозможность подтвердить пути реальных исходных файлов на ПК владельца без его проверки: наличие актуального `sout_path`, ресурсной MDB, `fgis_ra.ini` и внутренних XML зависит от рабочей оригинальной установки. **Точные пути на конкретном ПК неизвестны**.
- Issue #8 оставлена открытой до подтверждения обнаружения либо исправления по реальным данным; issue #2 требует независимого эталонного теста XML ФСА.

## После уточнения fgis_ra.ini и многопротокольной работы
- Реальное отсутствие `fgis_ra.ini` в показанном оригинальном Program Files подтверждено пользователем. Указанный файл — только дополнительный источник переопределений; его отсутствие не блокирует чтение MDB или поиск протоколов, но не позволяет достоверно применять пользовательские подмены. Не делать искусственный INI.
- Код пакетной диагностики без одного выбранного XML вошёл в main и прошёл CI #37880346284. Однако для проверки на настоящей рабочей базе владельца потребуется установленная новая версия; опубликованная v0.1.2 ещё без этого изменения.
- Без подтверждённой эквивалентности всех ФСА данных полный рабочий XML не формировать. Issue #8 остаётся открытой до пользовательских испытаний новой версии.
