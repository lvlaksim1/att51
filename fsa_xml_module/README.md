# Самостоятельный модуль формирования XML для ФГИС ФСА

**Состояние: первая проверяемая реализация, не готово для рабочей выгрузки.**

Цель владельца: воспроизвести существующий алгоритм «Аттестация-5.1 (СОУТ)» версии 5.1.1739 без запуска самой программы или Microsoft Word. **Источники сохраняются оригинальными:** рабочая Access MDB, каталог `<имя БД>_files` с XML измерительных протоколов, рабочая ресурсная `res_orgs.mdb`, настройки `options.ini` и `fgis_ra.ini`, XSD `fileProtocolLoad_v4.xsd`. Исходные файлы в `extracted/` не изменяются.

## Реализовано сейчас

- Поиск связанного каталога `*_files` по правилам `v5_attest_DB.read_db_path`.
- Открытие оригинальных `.mdb` через **ADO / Jet или ACE OLE DB** в режиме чтения (**Windows; не требуется Word**).
- Перечисление рабочих мест из `struct_rm`, связанных протоколов из `sout_factors` с подтверждёнными условиями отбора оригинала.
- Определение исходного внутреннего XML из поля `sout_factors.file` по правилу `doc_to_xml2`.
- Отбор протоколов по `select_individual` и `select_consolidated`: запрос `sout_factors`, исходный `docs_list.xml`, сводные протоколы в `sv_docs/`, фильтры факторов и выбранных подразделений, признаки устаревшей формы НД.
- Первая перенесённая измерительная ветвь: `v52_exp_fgis_ra2025.read_ekv_shum_param` для шума (фактор 4). Переносятся значения и штатные идентификаторы `9`/`3472`, `281`, `650`, а также условия четырёх переключателей и неопределённость. Результат пока **промежуточный**, не выходной XML ФСА.
- Чтение основных атрибутов `Document`, `factor`, `si_guids`, `persons`, `nd_data`, учёт `fgis_state=1`, проверка наличия файла и связи оборудования с таблицей `FGIS_RA` в ресурсной MDB.
- Самостоятельная запись **тестового подмножества** итогового `root/protocol` через `serialize_protocols` (**только с явным `synthetic_test_mode=True`; рабочая генерация заблокирована**), деление по 100 протоколов, сохранение порядка штатных полей, обработка готовых PDF/DOCX-вложений.
- Проверка XML по **исходной схеме** `extracted/app/fileProtocolLoad_v4.xsd`: MSXML 6 на Windows или lxml в среде разработчика.

## Пока не реализовано — обязательно до рабочей эксплуатации

1. Доработать уже существующие два механизма отбора до полной совместимости с исходными деревьями рабочих мест и всеми фильтрами интерфейса.
2. Полное преобразование `v52_exp_fgis_ra.FillPrototcolData`, `get_xml_data_sv` и `v52_exp_fgis_ra2025.get_ResearchObjects2025` для всех факторов измерений. Пока перенесена только ветвь шума; дальнейшие сопоставления `get_DocNameId`, `ResearchObjectInfo` ещё отсутствуют.
3. Полные связи `ATT_DEVICE`, `ATT_PERSON`, `DIC_ND`, нормативные методики, роли/подписи, адреса организации из рабочих настроек.
4. Отсутствующие разделы итогового XML (включая реальные `ResearchObjectInfo`, адреса, пользователей и дополнительные настройки). Пока `serialize_protocols` предназначена **только для проверки границы сериализации**, а не для подачи на портал.
5. Эталонное сравнение побайтового/смыслового содержания с реальным XML, созданным оригинальной программой на идентичных входных данных.

**Запрещено считать сообщение `XML conforms to original XSD` доказательством корректной выгрузки.** XSD проверяет форму и типы, но не полноту прикладных сведений и не эквивалентность алгоритмов.

## Диагностика источников

Требуется Windows с 32-разрядным Jet OLE DB 4.0 либо установленным подходящим ACE OLE DB, Python 3.10+ с pywin32 (`python -m pip install pywin32`). Разрядность Python должна соответствовать установленному провайдеру. Доступ к базам выполняется без их изменения. Вставлять в репозиторий действующие рабочие базы, содержащие персональные сведения, не нужно.

```powershell
cd fsa_xml_module
python -m att51_fsa inspect --mdb "D:\Data\ARMv51.MDB" --resources "D:\Resources\res_orgs.mdb" --rm-id 123 --output source_audit.json
```

Диагностика без `--rm-id` охватывает базу без воспроизведения выбора иерархии и регионов в оригинальном интерфейсе. Для точного отбора выбранные РМ необходимо передавать явно. Каталог документов по умолчанию выводится из имени MDB, но может быть явно указан через `--files`.

Диагностический отбор по выбранным пользователем рабочим местам (не формирует итоговый XML):

```powershell
python -m att51_fsa select-individual --mdb "D:\\Data\\ARMv51.MDB" --files "D:\\Data\\ARMv51_files" --rm-id 123 --factor 4 --factor 9
```

Отбор сводных протоколов организации из штатного `docs_list.xml`:

```powershell
python -m att51_fsa select-summary --files "D:\\Data\\ARMv51_files" --organization-guid "GUID_организации" --visible-division "ceh_1" --factor 4
```

Извлечение промежуточных данных измерений шума:

```powershell
python -m att51_fsa inspect-noise --xml "D:\\Data\\ARMv51_files\\RM\\xml\\Noise.xml" --acoustic --per-operation --uncertainty
```

Флаги соответствуют переключателям исходного VBA. Эти команды **не создают итоговый XML ФСА**.

Проверка уже созданного XML по штатной схеме:

```powershell
python -m att51_fsa validate --xml "D:\Export\fsa_prot.xml" --xsd "..\extracted\app\fileProtocolLoad_v4.xsd"
```

**Рабочая генерация из MDB пока сознательно недоступна через командную строку и программный интерфейс; `serialize_protocols` допускает только явный синтетический испытательный режим.** Это исключает создание правдоподобного, но содержательно неполного XML.
